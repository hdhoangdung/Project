SRS Compliance Report

This report maps each SRS requirement to the implementation files or notes.

1. System Architecture Requirements
- OOP + MVC: Project root `c:\xampp\htdocs\Projects_\mvc` with `app/Controllers`, `app/Models`, `app/Views`.
  - Core classes in `core/Database.php`, `core/Controller.php`, `core/Model.php` (PDO, prepared statements).
  - Public router: `public/index.php` supports `index.php?c=Controller&m=Method`.

2. Modules
- Exactly four modules implemented as controllers:
  - `App\Controllers\CustomerController` (customer module)
  - `App\Controllers\VehicleController` (vehicle module)
  - `App\Controllers\ClaimsController` (claims module)
  - `App\Controllers\AccountingController` (accounting module)
  Each has corresponding models under `app/Models` and views under `app/Views`.

3. Global System Requirements
- Single shared DB config: `config/config.php`.
- Shared CSS/JS: `public/assets` (placeholders), original UI files preserved in Projects_ folders and included by controllers.
- Central upload directory: `public/assets/uploads`.
- Soft delete: `Model::softDelete()` sets `TrangThai=0` and controllers call softDelete.
- Logging: `core/Database::logAction()` writes into `qlbh_lichsu`.

4. Unified Database Design
- SQL schema in `sql/schema.sql` defines all tables: `qlbh_khachhang`, `qlbh_xe`, `qlbh_hopdong`, `qlbh_yeucau`, `qlbh_thamdinh`, `qlbh_pheduyet`, `qlbh_phieuthu`, `qlbh_phieuchi`, `qlbh_taikhoan`, `qlbh_lichsu`.

5. Data Integrity Rules
- Implemented checks in controllers/models:
  - `Customer::hasRelations()` prevents delete if linked.
  - `Vehicle::hasContract()` prevents delete if used in contract.
  - `ClaimsController::submit()` checks `Hopdong::isExpired()` before creating claim.
  - `AccountingController::receipt()` checks `Hopdong::totalPaid()` to prevent overpayment.
  - `AccountingController::payout()` checks `PheDuyet.TrangThai` before creating payout.

6. Router
- `public/index.php` implements OOP router format `index.php?c=Controller&m=Method` and maps to controllers/classes.

7. Module Details
- Customer module includes create/edit/soft delete/list and `createContract` as required.
- Vehicle module includes add/edit/list/soft delete and duplicate checks.
- Claims module implements submit, assess, approve, pushToAccounting flows.
- Accounting module implements receipt and payout flows and status validations.

8. Business Flows
- Flow A/B/C implemented across controllers and models (see `CustomerController::createContract`, `AccountingController::receipt`, `ClaimsController` methods, and `SearchController` for deep search).

9. User Roles
- Exactly 4 roles in `qlbh_taikhoan` seeded via `sql/seed.sql` and enforced by `Core\Controller::requireRole()` in controllers.

10. Security
- OOP session handling in `Core\Controller`.
- Password hashing verification used in `AuthController` (seed file contains sample hashes; replace with your own hashed passwords using PHP's `password_hash`).
- PDO prepared statements used in models.
- Server-side validations added in controller methods.

11. UI Preservation
- Controllers attempt to include original UI files from Projects_ folders (e.g., `c:\xampp\htdocs\Projects_\1\...`). When originals are missing, pure-HTML fallback views are used under `app/Views`.

12. Logging
- `qlbh_lichsu` is used; `core/Database::logAction()` writes User, Action, Timestamp, OldData, NewData, IP.
